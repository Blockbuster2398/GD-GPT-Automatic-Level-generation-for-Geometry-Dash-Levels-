# GD-GPT: Automatic Geometry Dash Level Generation

GD-GPT is a research prototype for converting Geometry Dash `.gmd` levels into a compact token sequence, training a PyTorch Transformer on those sequences, and sampling new levels back into `.gmd` files.

## Showcase

[Watch the showcase video](https://github.com/user-attachments/assets/07b4dbcf-4c04-40fe-9e1d-e7b7886be293)

## What the project does

- Reads Geometry Dash export files. A `.gmd` file is an XML property list whose `k4` field contains URL-safe Base64 and gzip-compressed level data.
- Maps raw object IDs to categories such as blocks, spikes, pads, portals, orbs, and speed changes.
  <img width="1369" height="750" alt="image" src="https://github.com/user-attachments/assets/13517819-0df1-4a50-87fe-338477dcd052" />
- Converts object placement into tokens for horizontal and vertical movement, object type, rotation, and gameplay state.
- Trains an autoregressive Transformer with PyTorch on tokenized levels.
- Generates token sequences from a prompt, with optional portal balancing and dynamic temperature adjustment.
- Decodes generated tokens into objects and writes playable `.gmd` output.
- Includes training, validation, benchmark, conversion, and generated-level directories for experimentation.

This is an experimental codebase. Generated levels may contain invalid geometry, unsupported objects, or gameplay that needs manual cleanup in the Geometry Dash editor.

## Requirements

- Python 3.14 or newer
- PyTorch 2.11 or newer
- NumPy 2.4 or newer
- A CUDA-capable GPU is recommended for training, but generation falls back to the CPU when CUDA is unavailable.
- Geometry Dash is required to open and play exported `.gmd` files, but is not required for tokenization or model training.

Install the project dependencies from the repository root:

```powershell
python -m pip install -r requirements.txt
```

The project metadata is also defined in `pyproject.toml`, so an environment manager such as `uv` can install it with:

```powershell
uv sync
```

## Quick start: convert a level

The root entry point demonstrates the complete parse, tokenize, decode, and export loop. It currently uses `main_levels/Theory Of Everything.gmd` and the checked-in full token dataset by default.

```powershell
python __main__.py
```

The reconstructed file is written to `conversion_output/output.gmd`.

For library use:

```python
from classes.Level import GMD_Level

level = GMD_Level("myLevel.gmd", keepDetail=False)
print(level.tokens[:20])

objects = GMD_Level.decode_tokens(";".join(level.tokens))
reconstructed = GMD_Level(objects_list=objects)
reconstructed.create_gmd(
	"conversion_output/reconstructed.gmd",
	"reconstructed_level",
	"Generated by GD-GPT",
)
```

`GMD_Level` also accepts `keepDeco=True` when uncategorized decorative objects should be retained during parsing.

## Prepare datasets

Training data is stored as semicolon-separated token text. To tokenize the level folders under `training_data_levels/dataset_*`:

```powershell
python processes/prepare_training_data.py
```

This script writes `resources/data_tokenized_sorted.txt` and prints token frequencies. The training scripts use prebuilt files under `training_data_levels/full_datasets/`; make sure the expected dataset file exists before training.

To create the JSON token benchmark from the levels in `main_levels`:

```powershell
python processes/create_benchmark_data.py
```

This writes `benchmark_levels.json`.

## Train a model

Training is currently interactive. The standard trainer asks whether to load a checkpoint and then asks for a new model name:

```powershell
python model/train_model.py
```

The optimized trainer uses the sorted dataset and adds CUDA mixed precision, gradient accumulation, and strided training windows:

```powershell
python model/train_optimized.py
```

Each trained model is stored under `model/models/<model-name>/` with its Transformer weights, vocabulary, hyperparameters, and checkpoint metadata. Training can take substantial time and GPU memory.

## Generate a level

`model/run_model.py` loads a trained model from `model/models/<model-name>/`. The example at the bottom of the file can be run directly:

```powershell
python model/run_model.py
```

Generated files are placed under `generated_levels/<model-name>/`. For programmatic generation, call `generate_level`:

```python
from model.run_model import generate_level

generate_level(
	model="your-model-name",
	prompt="start;x_increment-30;full_block;end",
	level_length=1000,
	seq_length=400,
	temperature=0.8,
)
```

The prompt is a semicolon-separated token sequence. Lower temperatures usually make sampling more conservative; higher temperatures increase variation. `boost_portals` and `dynamic_temperature` can be disabled when reproducibility or unmodified sampling is preferred.

For batch generation over prompt levels, use the benchmark runner:

```powershell
python processes/run_benchmark.py
```

Update the model name and generation settings in that script before running it.

## Token format

Tokens are separated by semicolons. Spatial movement is represented with increments such as `x_increment-30` and `y_increment-10`; objects use category tokens such as `full_block`, `spike-0`, and `ship_portal`; state tokens track modes, speed, size, and dual mode. The decoder turns these tokens back into positioned `GMD_Object` instances.

The parser intentionally supports a focused subset of Geometry Dash objects. Unknown or unsupported object IDs may be marked as modified, omitted from the token stream, or represented by `_` depending on the current detail settings. Use levels from GD versions 1.0-1.9 for best results

## Notes for contributors

- Most scripts assume they are run from the repository root.
- Model checkpoints are local artifacts and may be large. Keep generated experiments and private datasets out of commits unless they are intentionally part of the result.
- The format details in `guideline.md` are useful when extending the object map or adding new token categories.
